# Agent framework decision matrix

**For:** technical and business leaders choosing how to build an AI agent over their own systems. **Date:** November 2026. **Author:** Manuel Corona, independent AI architect.

**Bottom line**
1. **The framework does not decide quality; the model, the prompt and the tools do.** The same agent (same prompt, model, tools and limits) scored the same in every framework we measured: LangGraph 0.900 and Strands 0.900 on 40 tasks with identical failures; on 20 tasks, 0.950–1.000 across all four frameworks and our own loop.
2. **What differs is everything around the agent:** provider support, protocols, security hooks, state, observability, where it can be hosted, how much it costs per task, and how hard it is for a team to learn. That is what this matrix scores.
3. **Default recommendation:**
    - **LangGraph** for most clients (Google Cloud, OpenAI shops, prototypes).
    - **Strands Agents** for AWS clients and when OpenTelemetry observability matters.
    - **No framework** for a single, narrow agent under a strict dependency policy.
    - **Avoid multi-agent** unless a boundary forces it.

The scores, weights and totals below are generated by [`eval/matriz.py`](../eval/matriz.py). Change the weights for your company and re-run it (see [Adjusting the weights](#adjusting-the-weights-for-your-company)).

## Recommendation by scenario

| Scenario | Recommendation | Deciding factor | Watch out for |
|---|---|---|---|
| **Client on AWS** | **Strands Agents on AgentCore Runtime** | Measured deployment on AgentCore (READY in 35 s, same quality and model cost as local) plus native OpenTelemetry | Cold start of 5.7–5.9 s per new session, so reuse sessions for chat. A2A is v0.3 only. Run tools sequentially (concurrent by default) |
| **Client on Google Cloud** | **LangGraph**, with Google ADK as a close second | LangGraph runs on Vertex AI Agent Engine and keeps the model choice open. ADK wins if the client is committed to Gemini and Vertex | ADK forwarded the whole MCP result to the model: +53% cost with Claude, so cap tool output tokens. ADK's A2A server does not enforce the auth it declares |
| **Client standardized on OpenAI** | **LangGraph**; OpenAI Agents SDK only for an all-OpenAI stack that accepts 0.x | Native OpenAI support in both. LangGraph keeps portability, checkpoints and a 1.x API | Turn off the SDK's default tracing to OpenAI if data residency applies. Test every LiteLLM parameter at request level |
| **Regulated multicloud enterprise** | **Tie: Strands or LangGraph** (85% stable). Pick Strands if OpenTelemetry to your own collector is mandatory; LangGraph if checkpoints and portability across clouds weigh more | Security, observability and cloud independence | Neither framework enforces your permissions: keep scopes, a database role per profile, and an MCP gateway with client-side defenses (38/38 in both). Keep the identity provider your own (AgentCore cannot use a private one) |
| **Startup prototype** | **LangGraph** | Fastest to build here (145 lines, 12 minutes), checkpoints and human approval built in | Add OpenTelemetry or LangSmith before production, because the library emits no spans |
| **Small team, one agent, strict dependency policy** | **No framework** (the week 13 loop), tied with Strands (78% stable) | 0 dependencies, cheapest per task ($0.0027), the strongest security record | You own retries, timeouts, traces and provider changes. ## When not to use multi-agent

Measured in [A7](multiagente.md). A supervisor with three specialists (SQL analyst, business rules, and purchasing over A2A) against the single agent, on the same composite and rule tasks:

| | Multi-agent | Single agent |
|---|---|---|
| Success | 0.889 | 0.889 |
| Cost per task | $0.0067 (1.7×) | $0.0039 |
| Latency p50 / p95 | 28.6 / 47.9 s (3×) | 9.4 / 19.5 s |
| Model calls per task | 14.3 | 4.2 |

**Do not use multi-agent when:**
- One team owns the whole task and the data sits behind one set of tools. Splitting did not fix a single failure; both versions failed the same task.
- Latency matters to the user. Every delegation is another model round trip.
- The budget is tight. Each specialist re-reads context the single agent already had.

**Use it when a boundary forces it:**
- A capability belongs to another team, vendor or framework, and must be reached through a protocol (A2A) with its own audience, a validated Agent Card and a shared budget.
- A step must never hold credentials, such as purchasing or payments. A separate agent with no tools can propose; the orchestrator writes with the user's permissions, and a human approves.

## What was not measured

- The 38-case poisoning suite ran only on LangGraph and Strands. OpenAI Agents SDK and ADK are scored **N** on security for that reason.
- Managed hosting was measured only for Strands on AgentCore. LangGraph on LangSmith or Vertex AI Agent Engine, ADK on Vertex, and the OpenAI SDK self-hosted are **D** or **N**.
- Model portability was measured only with Claude. Fit with OpenAI or Gemini models is scored **N**. The Google Cloud and OpenAI scenarios rest partly on those cells, so before committing, run a 20-task spike with the client's own model (about $0.10 with the harness here).
- Team learning curve is one experienced engineer's build time and line count, not a study across teams.
- The spikes ran 20 tasks once; their success rates (0.950) are not distinguishable from 1.000.

## Adjusting the weights for your company

Write a JSON file with your model provider (`anthropic`, `openai`, `gemini`, `multi`), your platform (`aws`, `gcp`, `ninguna` = no preference) and 100 points over the 10 criteria:

```json
{"proveedor": "multi", "nube": "aws",
 "pesos": {"modelo": 15, "nube": 10, "protocolos": 5, "seguridad": 25, "estado": 10,
           "observabilidad": 10, "despliegue": 10, "madurez": 10, "curva": 0, "costo": 5}}
```

```bash
cd semana-15 && python eval/matriz.py --pesos my_company.json
```

It prints the ranking for your weights. The scores and their evidence stay fixed in [`eval/matriz.py`](../eval/matriz.py). When a new measurement changes a score, change it there, cite the evidence, and run `python eval/matriz.py` to regenerate this document.
