# Exit criteria by phase

This file records the exit criteria of each phase of the lab, with the evidence and the PR that verified each one. A criterion is checked only when its evidence is in the repository; anything that does not meet it stays marked as pending until it is resolved. The summary of capabilities, key results and the quickstart is in the [root README](../README.md).

## Repository map

| Phase | Weeks | Topic |
|---|---|---|
| 1. LLM fundamentals | `semana-01` to `semana-04` | A mini-GPT in MLX, tokens and sampling, to fine-tune or not (LoRA), local inference vs. an API |
| 2. Prompts, evals and NLQ | `semana-05` to `semana-07` | A versioned prompt library, regression evals in CI, bilingual NLQ over an inventory database |
| 3. RAG and data | `semana-08` to `semana-12` | Retrieval, advanced and multi-tenant RAG, a legacy schema and non-text documents, RAG evaluation, managed RAG on AWS and Google Cloud |
| 4. Agents and MCP | `semana-13` to `semana-18` | Workflows vs. agents, the Claude Agent SDK, a remote MCP server with OAuth, multi-agent systems, reliability |
| 5. LLMOps and multicloud production | `semana-19` to `semana-24` | LegacyBridge deployed in the client's cloud with IaC, cost control, red teaming and a second cloud |

Each week has its own `README.md` with method, results, cost and decisions; the figures link to `resultados/`.

## Requirements

- macOS on Apple Silicon for Phase 1 (MLX); Linux or macOS for the rest.
- [uv](https://docs.astral.sh/uv/) and Python 3.13; Docker for PostgreSQL with pgvector.
- API keys are never in the repository: they are read from local environment variables and, in CI, from repository secrets.

## Phase 2 exit criteria

Each week of Phase 2 closes only if it meets the following:

- [x] Prompts and evals live in Git with versions (`semana-05/prompts/`, `semana-06/golden/`).
- [x] There is an automatic regression eval (`semana-06/evaluar.py`) that runs in GitHub Actions when prompts, evals or `semana-07/` change.
- [x] Prompt or model changes go through a pull request, not a direct push to `main`, with the `ProteccionRama` branch protection and the `regresion` check as a requirement (verified with PR #2).
- [x] The NLQ eval (week 7) runs on every PR, with Haiku on the hard set and a CI database with synthetic data from seed 42. Verified in PR #3 (accuracy 0.953 in Spanish and 1.000 in English); threshold 0.90 from the next PR on.
- [x] Each week publishes its results in its README, with cost and accuracy per model.

## Phase 3 exit criteria

Phase 3 covers weeks 8 to 12: retrieval, advanced RAG, the integrated assistant (8 to 10), RAG evaluation (11) and managed RAG in the cloud (12).

- [x] The retrieval eval runs in CI on every PR that touches `semana-08/**` or `semana-09/**`, with a recall@5 threshold per language (0.90), calibrated with the first run (ES 0.990, EN 0.950). Verified in PRs #15 and #17 for week 8 (`semana-08/resultados/ci_recuperacion.md`) and in PR #29 for week 9 (`semana-09/resultados/ci_semana09.md`).
- [x] There is a documented comparison of chunking, embeddings and vector databases with recall@k, latency and cost, in ES and EN (`semana-08/README.md`, activities 2 to 5; chunking in `semana-08/resultados/chunking.md`, recorded on 2026-10-26).
- [x] Hybrid search and reranking are measured against the baseline. Reranking: nDCG@10 ES 0.904 → 0.982, EN 0.885 → 0.974. Hybrid search (BM25 + vector with RRF): it does not improve recall@5 (ES 1.000 → 0.970, EN 1.000 → 0.770) and is not adopted (`semana-08/resultados/hibrida.md`).
- [x] Answers with citations are evaluated with a judge, with accuracy and citation precision reported (`semana-08/README.md`, activity 8).
- [x] Advanced techniques (query rewriting, HyDE and contextual retrieval) are measured on the same frozen gold set and are adopted only if they improve. All three are measured; none beats the baseline and none is adopted (`semana-09/resultados/comparacion_final.md`; PRs #19, #20, #21 and #23).
- [x] Tenant and role filters are applied inside the query in pgvector, Qdrant and OpenSearch, with a permission leak rate of 0 and a cross-tenant test. A non-negotiable criterion. Verified with 0 leaks in all three databases (PRs #25 and #26) and with a CI check that fails on any leak in every week 9 PR (PR #29).
- [x] Text-to-SQL over a legacy schema (views with cryptic names) is measured by execution in three variants (no dictionary, the full dictionary and a retrieved dictionary) against the original schema with the same model, with cost and latency. Verified with Sonnet 5.5 and Haiku 5.5 on the week 7 hard set: with Haiku, no dictionary ES 0.884 / EN 0.953, full dictionary 0.977 / 1.000 ($0.00033 per question), retrieved dictionary 0.767 / 0.721; original schema 0.977 / 1.000 (`semana-10/resultados/sql_legado.md`; PRs #35 and #37).
- [x] Non-text documents (PDFs with tables, OCR scans and images) are extracted and indexed, and their accuracy is measured against the frozen reference (per-cell accuracy, character error rate and correct answers), as well as recall after indexing. Verified: intact rows pypdf 0/13, pdfplumber and Haiku 13/13 (PR #38); CER Tesseract 0.009, Haiku 0.001 (PR #39); associated facts in images Tesseract 0/7, Haiku 7/7 (PR #40); recall@5 of the extracted content measured for all three and in CI (1.000 per language, PR #44).
- [x] The integrated assistant (NLQ + document RAG) is measured by question type (SQL, document, non-text and mixed): routing, accuracy with citations, cost and latency. Its security is non-negotiable: zero SQL writes, 0 leaks by role and across tenants through the assistant, and no injected instruction in documents executed, with a CI check. Verified: routing ES 0.882 / EN 0.863 (PR #41); judged accuracy 0.961 / 0.980 vs. 0.294 SQL-only and 0.608 documents-only, with citation precision, cost ($0.00083 per question) and latency (p50 5.3 s) by type (PR #42); with the hardened NLQ, 0 writes, 0 leaks in 128 cases and 0/48 instructions obeyed (PR #43); the `eval-semana-10` check on every week 10 PR (PR #44). The security tests found that the activity 7 SQL connection allowed writing large objects (`lo_create`); this was fixed, and the assistant uses the hardened NLQ from PR #44 on (`semana-10/README.md`).
- [x] Retrieval and generation are evaluated with separate suites: recall@k for retrieval, and faithfulness and answer relevancy (RAGAS) for generation, with cost per query. Verified: a retrieval suite with recall@k, MRR, nDCG@10 and AP@5 (plus RAGAS context precision and context recall) that detects the reranking gain (AP@5 +0.070 ES / +0.095 EN, 95% CI excluding 0; PR #51); faithfulness and answer relevancy validated on known failures before use (PR #52); a generation suite with fixed contexts: accuracy 1.000, faithfulness 0.679 / 0.805, answer relevancy 0.890 / 0.860, correct abstention 20/20 (PR #53); each suite moves only with its own component (PR #55); cost per query: answering $0.00070 (p50 4.2 s) and evaluating $0.00141, $0.28 per CI run (PR #56); both suites run in CI with thresholds, in separate jobs (PR #57) (`semana-11/README.md`).
- [x] The same document base is loaded into a managed RAG service on AWS (Bedrock Knowledge Bases) and on a second cloud (Azure AI Search or Vertex AI Search), and their quality, latency and cost are compared on the same gold set. Verified with Vertex AI Search as the second cloud: the frozen package (SHA-256 per file) in 4 Bedrock knowledge bases on S3 Vectors and 2 Vertex data stores, measured with the week 11 gold set (150 questions) and the same evaluator. With the in-house chunks, Bedrock reaches accuracy 0.985 and Vertex with the semantic ranker reaches MRR 0.977 / 0.962, vs. 1.000 for the in-house pipeline; with managed ingestion and the common generator, 0.71 to 0.92 (0.969 with the BDA multimodal parser and RetrieveAndGenerate). p50 latency from 1.5 s (RetrieveAndGenerate) to 3.9 s (in-house); cost from $0.00027 (Bedrock `Retrieve`) to $0.0012 per query (Vertex). 0 leaks in 672 queries (PRs #59 to #66; `semana-12/README.md`, `semana-12/resultados/comparacion.md`).

## Phase 4 exit criteria

Phase 4 covers weeks 13 to 18: agents, MCP and orchestration over legacy systems. The program closes it with a whiteboard design (in 30 minutes, a multi-agent system with MCP, its security boundaries and how it is evaluated) and with the CCAR-P certification. To verify it in the repository, there is one criterion per week plus the cross-cutting security criterion.

- [x] **13.** A LegacyBridge flow is implemented in at least two patterns (a workflow and an agent with the Claude Agent SDK), and success, cost and latency are compared on the same frozen gold set. Verified on 84 tasks with k = 3, Haiku 5.5 `low` and verification by execution. The workflow (the week 10 assistant with fixed routing) reaches pass@1 0.504, and the Claude Agent SDK agent 0.889 (+0.385, 95% CI [0.282, 0.496]); the agent wins on business rules (+0.806), compound tasks (+0.604) and ambiguous requests (+0.542), and ties on direct questions, where the workflow is cheaper ($0.0004 vs. $0.0018 per task) and faster (p50 3.0 s vs. 10.2 s). The agent with its own loop remains as a reference: 0.921, with no significant difference from the SDK (−0.032, CI [−0.071, +0.004]) (`semana-13/resultados/patrones.md`; PR #79 and the activity 10 PR).
- [x] **14.** A remote MCP server with OAuth over the LegacyBridge legacy database, with least privilege and tool-poisoning tests. Verified: MCP 2026-07-28 over Streamable HTTP on `127.0.0.1`, Keycloak as the authorization server (PKCE S256, RFC 8707 audience) and the MCP server as the resource server (RFC 9728 metadata, JWT validated with JWKS, 401/403 with step-up) (PRs #85 to #91). Least privilege in three layers: scopes, catalogs filtered by scope and one PostgreSQL role per profile; the week 13 `art_prv` finding is closed. Tool poisoning: with the client-side defenses (allowlist, hash pinning, a per-server prefix, results treated as data) 38/38 cases, 0 instructions obeyed, 0 writes and 0 leaks; without defenses, tool shadowing diverted 100% of the queries (PR #92). The week 13 agent over HTTP + OAuth reaches 0.900, the same as over stdio and within the interval of the 0.917 in-process result, with the same cost per task and +7 ms p50 per call; a role without the scope ends in refusal or abstention in 8/8 cases, with no leaks (PR #93). Claude Code connects with OAuth and receives only `legado:leer` (PR #94). The `eval-semana-14` check runs on every PR with an ephemeral Keycloak: 173 tests without the API and an agent mini eval with ES 0.90 / EN 0.90 thresholds and a $0.40 cap per run (PR #95). Cost of the week: $0.92 (`semana-14/README.md`).
- [x] **15.** The same agent in two frameworks, with a decision matrix for clients. Verified: the week 13 agent (same prompt, `responder` tool, limits, model and the tools of the week 14 MCP server with OAuth) in LangGraph (PR #101) and in Strands (PR #102), with the same 15 equivalence tests against the in-house loop. On 40 tasks with k = 3 they reach 0.900 and 0.900 with the same failures, and 38/38 poisoning cases each through an MCP gateway with the client-side defenses ($0.86; PR #103). OpenAI Agents SDK and Google ADK as spikes: 0.950 and 0.950 on 20 tasks; ADK costs 53% more because it forwards the full MCP result (PR #104). Multi-agent with a LangGraph supervisor and a Strands purchasing specialist over A2A, with a validated Agent Card and its own OAuth audience in Keycloak: 0.889, the same as the single agent, at 1.7 times the cost and 3 times the latency; injection over A2A treated as data, and proposals only in `PENDING_APPROVAL` (PR #105). Strands on Bedrock AgentCore with the key in AgentCore Identity: 1.000, the same as locally, with a 5.7 s cold start vs. 0.28 s warm; everything deleted and verified (PR #106). A decision matrix for clients with 10 criteria, evidence in every cell and 6 scenarios (PR #107). The `eval-semana-15` check runs on every PR with an ephemeral Keycloak: 111 tests without the API and a mini eval of LangGraph and Strands with calibrated thresholds (0.90 / 0.90 and 0.90 / 0.80) and poisoning 11/11 per framework, $0.40 cap (PR #108). Cost of the week: $1.78 in API usage and $0.024 on AWS, covered by credits (`semana-15/README.md`).
- [x] **16.** A reusable plugin or skill for clients, with its own eval. Verified: the Claude Code plugin `legacy-schema-audit` 1.0.0 audits a legacy schema read-only (data dictionary, ER diagram, risks with their `SELECT` and an executive summary) and installs from the repository's marketplace; a clean install from GitHub passes 20/20 (PRs #122 and #123). Its own eval: a frozen ground truth with 46 columns and 13 seeded risks (PR #113); `claude plugin eval` with 10 cases, Δ +0.57 over not using the plugin, and an in-house quality evaluator in which Sonnet with the plugin reaches PK/FK/PII 1.00 and 12 of 13 risks for $1.04, and Haiku 9 of 13 for $0.04 (PR #117); security 14/14 with Haiku and Sonnet in 7 cases (prompt injection, requests to change data, credentials, bypassing the hooks through Bash or a subagent, tool poisoning), with the real leak of a `~/.zshrc` contained and fixed (PRs #118 and #119). Spikes on a legacy screen: a browser agent 10/10 fields for $0.014 (PR #120) and computer use 10/10 for $0.0031 in a container without network access (PR #121). The `eval-semana-16` check runs on every PR with an ephemeral Postgres and Keycloak: `validate --strict`, 328 tests without the API and a mini eval with the API (5 deterministic cases and 2 real audits, with a read-only DSN and with a Keycloak token), with thresholds calibrated on 2 runs and applied on a third, 20 security controls without a threshold and a $0.40 cap per run (PR #124). Cost of the week: $0.35 in API usage; the rest with the subscription (`semana-16/README.md`).
- [x] **17.** Human-in-the-loop approval, guardrails and token budgets applied; a trajectory eval and a trace dashboard with OpenTelemetry GenAI or Langfuse. Verified: a LegacyBridge task is one OpenTelemetry GenAI trace (agent, model, MCP client and server, SQL) with a fixed shape, in a self-hosted Langfuse v4 through a Collector that redacts by allowlist (0 of 9 canaries leaked with content capture off and on; one project per tenant, with tested isolation). Budgets per task, session and tenant-day, calibrated with the week 13 distribution: 0 caps crossed in 84 paid tasks (#132). Input, tool and output guardrails: 0 obeyed, 0 writes and 0 leaks in 38 attacks; false positives measured on 84 tasks against a limit set in advance, and the guardrail that exceeded it ships in audit mode (#133). Human approval of purchase orders with the R-OC-APRUEBA level taken from Keycloak, a checkpoint in PostgreSQL and resumption: 0 orders without approval (#134). A trajectory eval read from the spans against frozen references, with scores in Langfuse: 91.7% (#135). A dashboard as code, a static export and a runbook (#136); security of the observability stack (#137); CI with an API mini eval and thresholds calibrated with the week 10 rule (#138).
- [ ] **18.** A whiteboard design of a multi-agent system with MCP, its security boundaries and its evaluation plan, done in 30 minutes and versioned; CCAR-P taken.
- [x] **Cross-cutting (non-negotiable):** zero unapproved writes, 0 leaks by role and across tenants, and no injected instruction obeyed, with a CI check. Verified in week 13 with 140 runs: the table fingerprints do not change, proposals stay in `PENDING_APPROVAL` without being executed, there are 0 leaks in 40 runs (24 by role and 16 across tenants), and 0 injected instructions in SQL data and in rules were obeyed (PR #80). The `eval-semana-13` check enforces it on every week 13 PR (PR #81). It is reviewed in every week of the phase and unchecked if any week breaks it. Week 14: it holds on the remote MCP server, with 0 writes, 0 leaks and 0 instructions obeyed in 38 poisoning cases, enforced by `eval-semana-14` on every PR (PRs #92 and #95). Week 15: it holds in the four frameworks and in multi-agent mode: 38/38 cases in LangGraph and in Strands (PR #103), 0 writes and 0 instructions obeyed over A2A (PR #105), and 11/11 cases per framework in `eval-semana-15` (PR #108).
